# FIT-CONNECT 운영 점검 기록 — 2026-11-23

## 범위와 완료 구분
이 문서는 **소스 코드에서 확인한 내용**과 **실제 운영환경에서 아직 검증하지 못한 내용**을 분리한다. 코드 업데이트/문법 검사가 운영 배포 성공, 데이터 안전성 또는 법적 준수를 증명하지 않는다.

### 이번 변경
1. 회원의 한 끼 식단에 `foods[]` 배열을 추가하여 음식 항목별 '양 수정'과 '삭제', 합계 자동 계산을 제공한다. 기존 `desc/cal/carb/prot/fat/photos` 필드는 계속 유지하므로 구버전 식단 화면과의 호환성을 유지하려 했다. 기존의 설명/칼로리 한 덩어리는 삭제되지 않고 '기존 식단 기록' 항목으로 표시된다.
2. 최근 선택 음식은 **세션 한정(sessionStorage)**으로 표시한다. 회원 토큰, 사진, 회원명 등은 최근 음식 목록에 저장하지 않는다. 브라우저 탭 세션 종료 시 사라질 수 있다. 이 기능은 기기 간 동기화가 아니다.
3. 코치 대시보드 '식단 미답변' / '운동 미답변' 필터를 추가했다. 기존 `pendingDiet`, `pendingWorkout`, `directPendingVideos` 자료를 그대로 사용하며 새로운 별도 서버 큐를 만든 것은 아니다.
4. 112종 음식의 현 수치는 **평균/추정치로 표시**한다. 국내 공식 데이터와 전 품목/1인분 값을 맞대조한 것은 아니다. 사용자에게 정확한 포장지·조리법을 우선할 것을 안내한다.
5. 소스 회귀 검사에 식단 항목/코치 필터의 존재 확인을 추가하고, 이전 매거진 배치 검사를 현재 의도대로 수정했다.

### 영양성분 공식 검증 미완료
- 공식 기준: 식품의약품안전처 K-FIND 식품영양성분DB https://various.foodsafetykorea.go.kr/nutrient/
- 원재료 기준: 농촌진흥청 국가표준식품성분표 10.4 (2026), 출처를 표시하고 재사용 조건 준수 필요
- 현 단계에는 음식별 공식 식품코드/시험 출처/측정 기준/검증일이 저장되어 있지 않다. **112종 전체 공식 검증 완료로 표시하지 말 것.**
- 다음 운영 작업: 공식 데이터 다운로드/API 사용 조건 확인 → 각 음식 검색명 매칭 → 생것/조리 후/가식부 구분 → 고정 중량 또는 1회 섭취량 검증 → 변경 내역 및 원본 출처 열 추가. 브랜드 제품은 제품별 영양표시 우선.

### 코드에서 확인한 안전장치
- 회원 세션 서명 검증(8시간 제한)과 토큰 검증 경로가 Worker에 있다. 실제 운영환경의 비밀키 설정·교체 여부는 확인하지 못했다.
- 식단 사진은 Worker `dietSave`에서 별도 저장 및 기존 사진 유지 병합 처리를 시도한다. 클라이언트에서 Apps Script 텍스트 저장 다음 Supabase 식단 저장 순서로 수행한다.
- 저장 실패 시 메시지 표시, 사용자의 입력 폼 유지, 운동 저장 재시도 로직이 소스에 있다.
- 트레이너 미답변 상태는 날짜별 피드백 자료를 이용해 요약한다.

### 운영/보안 위험 및 필수 수동 검증 (아직 미완료)
1. **부분 저장:** Apps Script 쓰기는 성공했지만 Supabase `dietSave`에 실패할 수 있다. 두 저장소 간 원자적 트랜잭션이 없다. 실패 안내만으로 일관성을 보장하지 못한다. 읽기 재검증/재시도/동기화 복구 설계 필요.
2. **개인정보 캐싱:** 일부 회원 토큰과 운동·식단 기록이 브라우저 localStorage 캐시에 존재한다. 공용 기기나 탈퇴/로그아웃 시 잔존 위험 검토 및 삭제 정책 필요.
3. **공격 방어:** 코드 내 인증 흐름이 존재하지만 계정 잠금/레이트리밋, 비밀번호 회전, 권한 격리, 감사 로그, 모의침투 테스트는 확인되지 않았다. 특히 트레이너 비밀번호 공유 방식은 서비스 확대 전에 교체 권장.
4. **백업/복구:** Supabase PITR/백업 보존 정책, Google Sheets/Drive 별도 백업, 1건 복구 리허설 완료 여부 미확인.
5. **실사용 테스트:** 실제 iPhone Safari/PWA, 느린 모바일 네트워크, 이미지/영상 첨부, 트레이너-회원 동시 수정, 만료된 세션, 중복 탭 저장, 오래된 레거시 식단 불러오기, 개별 음식 전체 삭제 후 새로고침 확인 필요.
6. **법무/개인정보:** 개인정보 처리방침, 위탁·국외 이전 고지, 보유기간, 탈퇴/삭제, 사용자 데이터 열람·다운로드, 영양정보 면책 및 미성년자 이용 정책 점검 필요.
7. **배포:** GitHub main 변경만 확인. Cloudflare 반영/실제 빌드 실행 결과는 별도 확인해야 한다.

### 최소 승인 테스트
- 새 회원 시험 계정에서 아침에 계란 1개 + 밥 1공기 추가 → 두 항목이 각각 나타남 → 밥 양 수정 → 계란 삭제 → 저장 → 새로고침/다른 폰에서 동일한지 확인.
- 기존 식단의 텍스트/칼로리/사진이 유지되는지 확인. '기존 식단 기록' 항목을 삭제해도 다른 음식/사진이 삭제되지 않는지 확인.
- 마지막 음식 삭제 후 빈 한 끼 저장 및 새로고침 확인.
- 해당 회원 식단 기록 후 코치 '식단 미답변' 필터에 나타나고 코치 식단 피드백 후 빠지는지 확인.
- 저장 중 비행기 모드 전환 후 오류가 명확히 안내되고 데이터가 부분 저장됐을 가능성을 인지할 수 있는지 확인.
- 인증 없는 다른 회원 기록 API 요청이 거부되는지 서버 로그 및 격리 테스트 확인.
